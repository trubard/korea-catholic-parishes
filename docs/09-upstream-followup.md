## 1. `feast` 는 수집한 날에만 채워진다 — 설계를 다시 봐야 한다

### 무슨 일이 벌어졌나

`feast` 가 붙은 항목이 **17,240건 중 1건**이다.

```text
국군중앙주교좌 [토요일] 10:30  feast="성모승천대축일"  note=null
```

06 §11-2 에서 보고한 건수는 **465건**이었다. 두 자릿수가 아니라 세 자릿수 차이다.

### 원인 — 필드가 아니라 수집 시점의 문제다

커밋 메시지에 이미 적혀 있다. *"feast는 축일 근처 수집 때 채워짐."*

데이터가 그것을 확인해 준다.

| | |
|---|---|
| `generated_at` | 2026-08-15 |
| 그날은 | **성모승천대축일** (의무 축일) |
| 2026-08-15 의 요일 | **토요일** |
| 유일한 `feast` 항목이 있는 구간 | **토요일** |

수집일이 축일이었고, 그래서 그날 자리에만 값이 생겼다.
`note` 에서 `대축일` 을 찾으면 **0건**이다 — 축일 문구 자체가 원본에서 사라졌다.
즉 성당 홈페이지는 **그 주에만** 축일 안내를 띄우고, 지나가면 내린다.

### 그래서 문제가 되는 것

**`feast` 는 지금 형태로는 "이 성당이 축일에 어떤 미사를 하는가" 를 답하지 못한다.**
답하는 것은 "수집한 날이 축일이었다면, 그날 무슨 미사가 있었나" 다. 둘은 다르다.

소비 쪽은 축일 미사를 화면에 표시해야 하는데, 다음 성모승천대축일(2027-08-15)에
이 데이터를 쓰면 **1건 말고는 아무것도 모른다.** 그래서 우리는 결국
날짜로 판정하는 자체 로직(`holy-days.ts` — 한국 주교회의 의무 축일 4개 + 부활절 계산)을
**그대로 유지해야 한다.** 06 §15 에서 "`isFeastDayMass` 가 불필요해진다" 고 쓴 것은
**우리 예상이 틀렸다.** 정정한다.

### 제안 — 셋 중 하나

**(a) 축일 미사를 누적한다** — 값이 가장 크다.
수집일에 축일 문구가 잡히면 **덮어쓰지 말고 쌓는다.** 축일은 날짜가 정해져 있으니
한 번 잡은 것은 이듬해에도 유효하다.

```jsonc
"feast_masses": [
  { "date": "08-15", "feast": "성모승천대축일", "time": "10:30", "observed": "2026-08-15" }
]
```

`observed` 를 같이 두면 소비 쪽이 **얼마나 오래된 관측인지** 판단할 수 있다.

**(b) 최소한 문서로 명시한다** — 비용이 거의 없다.
`feast` 가 "수집일 한정 관측값" 이라는 것을 스키마 설명에 적어 준다.
그러면 소비 쪽이 **이 필드에 기대지 않는다** — 지금은 필드 이름만 보고
"축일 정보가 온다" 고 오해하게 되어 있다.

**(c) 지금 상태로 두되 이름을 바꾼다** — `feast_observed` 처럼.
이름이 한정성을 말해 주면 오해가 줄어든다.

> 소비 쪽 의견: **(b) 는 반드시**, 가능하면 (a). (a) 가 되면 우리 쪽
> `holy-days.ts` 의 날짜 판정을 **데이터로 검증**할 수 있게 된다 —
> 지금은 서로 대조할 방법이 없다.

## 2. `place` 미이행 — 공소 110건이 본당 미사로 보인다

06 §13-3 의 3단계다. `place` 가 붙은 항목은 **0건**이다.

`note` 에 `공소` 가 들어 있는 항목은 **110건**이고, 9개 교구에 퍼져 있다.

| 교구 | 건수 |
|---|---|
| 전주교구 | 38 |
| 군종교구 | 18 |
| 제주교구 | 17 |
| 인천교구 · 대구대교구 | 각 10 |
| 대전교구 | 6 |
| 의정부교구 · 마산교구 | 각 4 |
| 청주교구 | 3 |

```text
조치원   08:00  note="노송공소"           place=undefined
안면도   15:00  note="누동공소"           place=undefined
백마     13:30  note="임진강 공소"        place=undefined
목천     15:00  note="공소:넷째 주일"      place=undefined
```

### 왜 이게 다른 것들보다 급한가

**공소는 본당이 아닌 다른 건물이다.** 좌표도 주소도 본당의 것이라,
소비 쪽 화면에서는 *"조치원성당 08:00 미사"* 로 보인다.
사용자가 조치원성당으로 찾아가면 **그 시각에 그곳에는 미사가 없다.**

06 §12 표에 적은 그대로다 — *"찾아갔는데 없으면 낭패."*
다른 누락은 미사를 **덜** 보여주지만, 이건 **틀린 곳으로 보낸다.**

소비 쪽에서 `note` 에 `공소` 가 있으면 표시하는 임시 처리를 하고 있으나,
문자열 매칭이라 `공소:넷째 주일` 처럼 공소 **이름이 없는** 것은 구분하지 못한다.

### 제안

```jsonc
{ "time": "08:00", "place": "노송공소", "note": null }
```

이름을 못 뽑아도 **본당이 아니라는 사실만이라도** 표시해 주면 충분하다.

```jsonc
{ "time": "15:00", "place": true, "note": "공소:넷째 주일" }
```

한 가지 더: 공소 note 110건 중 **10건은 괄호가 안 닫혀 있다**(06 §7 의 길이·괄호짝
검사에 걸릴 것들).

```text
"충일 공소(73사단"
"교중) 공소주일미사 (둘째, 셋째, 넷째 주) 은점"
"공소미사) 2주: 운산 3주: 문정"
```

`성환` 은 한 항목에 공소 둘이 뭉쳐 있다 — 06 §16 잔여 케이스에 올렸던 그 건이다.

```text
성환 10:30  note="교중) 소동공소(첫째주 15:00 ) 신휴공소(둘째주 15:00"
```

## 3. 대상 어휘 — 5건 남았고, 대부분 오탈자다

06 §11-1 에서 83건이라고 보고한 것이 **5건으로 줄었다.** 어휘 확장이 잘 들었다.
남은 것을 그대로 옮긴다. 모두 `중고등부` 계열이다.

| 성당 | note | `audience` | 성격 |
|---|---|---|---|
| 염리동 | `중고/청년미사` | `["청년"]` | **슬래시로 이어진 대상** — 중고가 샌다 |
| 함안 | `청년부 중고부미사` | `["청년"]` | 띄어쓰기로 이어진 대상 |
| 녹번동 | `10:00 중고**증**부 미사` | — | 오탈자 |
| 상동 | `중고**둥**부미사` | — | 오탈자 |
| 산곡3동 | `중고생` | — | 어휘에 없음 |

### 둘로 갈린다

**(a) 여러 대상이 한 시각에 붙은 것** (염리동·함안 2건)
`중고/청년미사` 는 대상이 **둘**이다. 시각을 나눌 때 슬래시를 처리했듯,
대상도 구분자로 나누면 잡힌다. 앞의 것만 취하는 지금 동작은 뒤를 버린다.

**(b) 오탈자·어휘 밖** (3건)
`중고증부` · `중고둥부` 는 성당이 손으로 적은 오타다. 06 §8 과 같은 성격이라
**상류가 고칠 문제가 아닐 수 있다.**

> 다만 이것이 06 §14 에서 말한 **열거 방식의 한계**를 그대로 보여준다.
> `중고등부` 를 알고 `중고생` · `중고둥부` 를 모르는 상태는 어휘를 늘려도 계속 생긴다.
> §14 의 제안(모르는 낱말도 `audience_raw` 로 남기기)이 있으면
> 이 5건이 **조용히 사라지는 대신 원문으로 드러난다.**
> 건수가 작아서 급하지는 않다 — 다만 방향의 문제다.

## 4. 참고 — 바뀐 것 중 소비 쪽이 확인한 사항

문제는 아니지만 스키마를 쓰는 쪽에 알려 둘 만한 것.

| 관찰 | 값 | 판단 |
|---|---|---|
| `note: null` | 11,766건 | 이전엔 드물었다. 파서가 중복 note 를 정리한 결과로 보이며 **손실은 아니다.** 소비 쪽 타입이 `string \| null` 이라 문제없음 |
| `type` vs `audience`+`kind` | 4건만 불일치 | 하위호환 유지됨. 소비 쪽은 `type` 폴백을 당분간 유지한다 |
| `seasonal` | 20건 | `recurrence.season` 은 42건이라 **근거가 갈린다.** 어느 쪽이 정본인지 정해지기 전까지 소비 쪽은 계절 조건을 적용하지 않는다 (06 §6) |
| 미사시각 총계 | 17,240 | |

`seasonal` 과 `recurrence.season` 이 같은 사실을 두 자리에서 말하고 있다 —
06 §11-3 에서 지적한 **이중화**가 새 필드에서 재현된 형태다. 급하지 않지만
한쪽으로 모으는 편이 낫다.
